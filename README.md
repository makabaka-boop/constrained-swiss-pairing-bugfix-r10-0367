# Pairing Service

为 4～12 名选手编排下一轮瑞士制比赛的 HTTP 服务（Go）。输入每人的当前积分
（半分单位的整数）、此前每轮对手与执先颜色、已有轮空记录，输出一套**完整**
的下一轮赛程（含全部对局、执先颜色；奇数人数时恰好一人轮空）。

## 运行与测试

```bash
go run .                    # 监听 :8080，可用 ADDR 环境变量覆盖
go test ./...               # 单元/HTTP 测试 + 3000 例随机对拍
go test ./... -run Fuzz     # 额外 20000 例大规模对拍
```

## API

`POST /pair`，请求体：

```json
{
  "players": [
    {"id": "A", "score": 6,
     "history": [{"round": 1, "opponent": "B", "color": "white"}],
     "byes": []}
  ]
}
```

- `score`：以半分为单位的整数（1 分 = 2，平局 = 1）。
- `history[].color`：`"white"` / `"black"`，表示该选手自己的执先颜色。

响应：

| 场景 | HTTP | 体 |
| --- | --- | --- |
| 成功 | 200 | `{"status":"OK","result":{...}}` |
| 输入合法但不存在完整方案 | 200 | `{"status":"NO_PAIRING"}` |
| 输入结构不一致 / 非法 | 400 | `{"status":"INVALID_INPUT","error":"..."}` |

`result` 中：

- `games`：对局列表，按双方较小选手 ID 排序；`white` 执先。
- `bye`：轮空者 ID；偶数人数时为 `""`。
- `scorePenalty` / `colorPenalty`：两个目标值（便于对拍/审计）。

## 规则与拒绝条件

- 人数必须在 4～12；ID 非空且唯一；积分非负。
- 历史中同一选手同一轮重复出场（两条对局记录）→ 拒绝。
- 历史必须双向一致：A 记载第 r 轮对 B 执白，则 B 必须记载第 r 轮对 A 执黑；
  对手或颜色对不上、缺少对应记录 → 拒绝。
- 同一轮既有对局又有轮空记录 → 拒绝。
- 下一轮任何一对都不得重复交手。
- 奇数人数时恰有一人轮空；已有轮空记录者不能再轮空。
- 执先颜色必须使**每名**选手赛后 |执白次数 − 执黑次数| ≤ 2（轮空者颜色
  次数不变，同样受限）。
- 无完整合法方案时返回 `NO_PAIRING`，绝不交付部分赛程。

## 优化目标（严格字典序）

1. 最小化全部对局的双方积分差绝对值之和；
2. 在其并列时，最小化所有人赛后 |执白 − 执黑| 之和；
3. 仍并列时，取规范序列字典序最小者：对局按双方较小 ID 排序，依次编码
   `(执白, 执黑)`，末尾追加轮空者（偶数人数追加哨兵）。

## 实现

规模上限 12，求解器直接穷举：轮空人选 → 完美匹配（始终先配对当前最小
ID，保证对局按规范顺序生成）→ 每对两种执先方向（剪去赛后颜色差 > 2
的分支）。最坏匹配数仅约 1 万级，瞬时完成。

## 文件

- `types.go`：请求/响应类型。
- `validate.go`：结构校验与历史一致性检查。
- `solver.go`：穷举求解器（轮空 × 匹配 × 颜色方向 + 三级目标裁决）。
- `pairing.go`：库入口 `Pair`。
- `server.go`：HTTP 层（`POST /pair`、`GET /health`）。
- `*_test.go`：手写边界用例、独立穷举 oracle 对拍、HTTP 测试。



## 场地限制赛程
POST /pair/constraints 使用 players 和 constraints。constraints.fixed 为已确定执白/执黑的 Game 数组，forbidden 为禁止交手的无向选手对，byeCandidates 为本轮允许轮空者；null 表示全部，空数组表示无人允许。场地限制与历史重赛、颜色平衡、既有轮空规则共同满足，仍按原积分差、颜色差、规范序列全局择优。固定对局不得重复占用选手，未知/自身/重复禁止对或互相冲突约定按非法输入拒绝；历史导致约定无可行方案时 NO_PAIRING。新接口积分限定0..1000000，原 /pair 不变。
